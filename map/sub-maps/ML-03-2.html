Key Insights ​

  1. runToolUse() 是执行心脏 (1745 行)：完整的 7 阶段 pipeline（validate → permission → pre-hooks → execute → result-storage → post-hooks → telemetry），每个阶段都有详细的错误处理和遥测。

  2. 双模式执行: 传统 runTools() (分批串行/并行) 和 StreamingToolExecutor (边流边执行)，都调用同一个 runToolUse() 核心函数。

  3. 工具结果大小感知: toolResultStorage.ts 对大结果（>100KB）自动持久化到磁盘，返回截断 preview 给模型，防止 context 爆炸。

  4. BashTool 最复杂 (1143 行)：多文件安全体系（bashPermissions 2621行 + bashSecurity 2592行 + pathValidation 1303行 + readOnlyValidation 1990行），占总工具代码量的最大份额。

  5. AgentTool 递归调用 (1397 行)：子代理本质上是一个新的查询引擎循环（调用 query.ts），可递归嵌套。

  6. MCPTool 极简代理 (77 行)：不做任何处理，纯粹转发到 MCP server，是最薄的工具实现。
