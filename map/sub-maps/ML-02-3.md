## File Details

### src/services/api/claude.ts (3419 lines) — DEEP

**streamMessages()** — 核心流式 API 调用入口：
- 构建 `MessageStreamParams`（messages, tools, system, model, max_tokens 等）
- 通过 `createAPIClient()` 创建 Anthropic SDK client
- 调用 `withRetry()` 包装的流式请求
- 返回 `AsyncIterable<BetaRawMessageStreamEvent>`

**createStreamingRequest()** — 构建完整请求参数：
1. `normalizeMessagesForAPI()` — 消息格式化（→ messages.ts）
2. `toolToAPISchema()` — Tool 接口转 API schema（→ api.ts）
3. Cache control 标记（system prompt cache, ephemeral marks）
4. Betas 头构建（`getMergedBetas()`）
5. `max_tokens` 计算（`getModelMaxOutputTokens()`）
6. `thinking` 配置（extended thinking）
7. Tool choice 配置（auto / named / none）

**消息格式化管线**：
- `normalizeMessagesForAPI(messages)` → 转为 `MessageParam[]`
  - 处理 tool_result + tool_use 配对
  - `ensureToolResultPairing()` — 确保每对正确配对
  - `normalizeContentFromAPI()` — 内容标准化

**Stream 消费**（在 query.ts 的 for-await 中）：
- `text_delta` → 文本增量
- `tool_use` → 工具调用块
- `content_block_stop` → 内容块结束
- `message_delta` → stop_reason + usage
- `message_stop` → 消息结束

**getMaxOutputTokensForModel(model)** — 模型输出限制：
- sonnet/opus/haiku 各有不同默认值
- 支持 maxOutputTokensOverride（recovery 场景）

**createAPIClient()** — 创建 Anthropic SDK client：
- API key 从 `getAPIProvider()` 获取
- base URL 支持自定义（Bedrock/Vertex 等第三方）
- HTTP Agent 配置（proxy、timeout）

### src/services/tools/toolOrchestration.ts (188 lines) — DEEP

**runTools(toolCalls, toolUseContext, abortSignal)** — 工具执行编排：
1. `partitionToolCalls()` — 分组可并行 / 必须串行的工具调用
2. 并行组 → `Promise.all(runToolCall(...))`
3. 串行组 → 逐个 `runToolCall()`
4. 返回 `ToolResult[]`

**partitionToolCalls()** — 安全分组：
- 文件修改类工具（Edit, Write）→ 串行
- 读取类工具（Read, Glob, Grep）→ 并行
- 其他工具按安全策略分组

**runToolCall()** — 单个工具执行：
- `findToolByName()` 查找工具
- `execute()` 调用
- 错误处理 + result 格式化

### src/services/tools/StreamingToolExecutor.ts (530 lines) — DEEP

**StreamingToolExecutor** — 流式工具执行器（feature-gated）：
- **设计目的**：在 API 流还在发送 tool_use 块时就开始准备工具执行
- `feedToolUseBlock(block)` — 接收新的 tool_use 块
- `getRemainingResults()` — 获取所有已执行工具的结果
- 内部维护执行队列（`Map<toolUseId, Promise<ToolResult>>`）
- 支持并发执行（同 partitionToolCalls 逻辑）

**与传统模式对比**：
| 模式 | 触发时机 | 并发 | Feature Gate |
|------|----------|------|-------------|
| StreamingToolExecutor | tool_use 块到达时立即准备 | 自动并发 | STREAMING_TOOL_EXECUTION |
| runTools() | 全部 tool_use 块接收完后 | 显式分组 | 默认 |
