  • Key architectural insight:
    1. 双路径压缩架构：autoCompact 先尝试 sessionMemoryCompact（纯本地，无 API 调用），失败则 fallback 到 compactConversation（fork agent 发起独立 API 调用生成摘要）
    2. 四级压缩管线：applyToolResultBudget(工具结果预算) → snip(截断) → microCompact(微压缩工具结果) → context collapse(实验性，当前全 stub) → autocompact(全量压缩)
    3. contextCollapse/snipCompact/reactiveCompact 全是空壳 stub：外部构建时 DCE (dead code elimination) 消除，实际压缩仅依赖 compact + microCompact + sessionMemory 三条路径
    4. compact.ts 是最大文件 (1705行)：含 PTL retry（截断头部重试）、prompt cache sharing（tengu_compact_cache_prefix flag，默认 true）、pre-compact hooks 执行
    5. memdir 独立记忆系统：MEMORY.md 入口管理 + 目录扫描 + Sonnet sideQuery 选择最多 5 个相关记忆，4 种类型分类法 (user/feedback/project/reference)
    6. 熔断器机制：autoCompact 内置 3 次失败熔断（COMPACT_FAILURE_THRESHOLD=3），连续失败后跳过后续压缩尝试
    7. grouping.ts 独立拆出：解决 compact.ts↔compactMessages.ts 循环依赖 CC-1180
    8. memoryScan.ts 独立拆出：避免 findRelevantMemories 引入 sideQuery 和 API-client 链的循环依赖 #25372
